# Frame / 网页设计分析工作台

这是一个独立的静态网页子应用，用于逐模块分析参考网页、学习设计原则，并生成可交给任意编程 Agent 的分析与建站提示词。它不替换仓库根目录的个人作品集。

## 本地运行

首次在一台新电脑上运行时，在仓库根目录执行 `npm install` 和 `npm run browser:install`，再执行 `npm start`，打开 `http://127.0.0.1:4173/design-analyzer/`。页面会请求本机 Node 服务，通过 Playwright/Chromium 分析公开参考页。登录、验证码和无法公开访问的页面不在自动分析范围内。

## 使用流程

1. 填写公开参考网址、页面类型、用户和目标，点击“实际分析参考网页”。服务会在桌面和手机视口打开页面、滚动采样懒加载内容，采集截图、标题、文本、样式、图片与控件。
2. 在独立分析工作区校正按实采证据生成的模块目的、风格、组件、动效交互和专业判断；可添加、删除、上移或下移模块。
3. 提示词工作台会同步编辑内容，可选只分析、只搭建、分析并搭建，以及是否加入内置技能规则。
4. 在提示词工作台粘贴简历、公司、品牌和产品的真实信息，或上传图片、PDF、DOCX、TXT、MD、CSV、JSON。纯文本会提取并写入提示词；图片及其他二进制文件可标注用途、备注、预览/下载，提示词会告诉 Agent 应替换到哪个模块，并禁止虚构。
5. 复制提示词给支持浏览网页/写代码的 Agent，或导出 Markdown。生成的任务要求 Agent 先核验参考页，明确事实/推断/建议，不可编造无法观察到的内容。图片、PDF、DOCX 等文件不会随提示词发送；请下载后放入 Agent 可访问的项目目录或作为附件提供。
6. 设计知识页展示技能来源和术语；可下载 `skills/web-design-analysis/SKILL.md`，作为通用技能文件放入兼容 Agent 的 skills 目录。

当前网页分析引擎返回“浏览器实测 + 本地规则建议”，不连接云端大模型。它会明确显示未验证的交互，不会自动点击、播放声音或提交目标网站表单。部分滚动、悬停、登录后状态需人工检查。分析 API 仅监听本机回环地址，不能直接作为多人公网服务部署。

表单、模块草稿、资料文本和提示词保存在当前浏览器的 `localStorage`；上传的文件二进制存于浏览器 `IndexedDB`，不会上传至服务端，也不会自动同步到另一台电脑。需要迁移时下载上传文件到项目目录，并复制或导出提示词。单文件限 15 MB，最多保存 20 项；文本附件最多提取 20,000 字符。PDF、DOCX 暂不自动解析文字，请把关键事实粘贴到资料框。

## 内置技能方法

内置的是独立编写的、跨 Agent 的 `web-design-analysis` 技能综合方法，而不是把上游仓库文件原样复制进来。参考的公开项目为 Anthropic `frontend-design`、Vercel Labs `web-interface-guidelines` 和 Microsoft `frontend-design-review`；详情与上游链接见知识页面及技能文件。安装方式因 Agent 而异，下载后请遵循对应 Agent 的技能目录约定。

## 修改与验证

- 页面结构：`index.html`
- 视觉系统与断点：`styles.css`
- 工作区逻辑、模块建议、提示词模板与本地保存：`app.js`
- 可下载的通用技能定义：`skills/web-design-analysis/SKILL.md`

可在仓库根目录运行 `node --check analyzer.mjs`、`node --check design-analyzer/app.js` 与 `node --test`。实采模块应由使用者校正；页面脚本、滚动动画和交互结果不会被当作已验证事实，最终实施前仍建议人工核对截图与页面行为。

GitHub Pages 只托管静态文件，不运行网页分析所需的 Node/Chromium 后端。若要公开给他人在线使用，需将前端静态站和受网络出口隔离的分析 API 分别部署；API 必须继续执行公网 IP/重定向校验、限流、超时和资源限制。
